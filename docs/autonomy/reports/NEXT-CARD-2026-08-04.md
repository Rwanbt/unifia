## Correction — 2026-08-04 : « pousser pour obtenir un run CI » n'était pas réalisable

Cette carte a d'abord désigné le push comme la seule action à portée. **C'était
faux, et la vérification n'avait pas été faite avant de l'écrire.**

`git remote -v` donne :

```
origin  D:\AI-Workspace\hermes-data\work\unifia-sandbox\repo (fetch)
origin  D:\AI-Workspace\hermes-data\work\unifia-sandbox\repo (push)
```

`origin` est **le clone Hermes** — un dépôt que la mission interdit de modifier.
Un `git push origin` y aurait créé la référence `recovery/…`, c'est-à-dire une
écriture dans un dépôt protégé. Il n'y a par ailleurs **aucun remote GitHub**
configuré, donc aucun workflow distant à déclencher.

### Mesure de protection appliquée

Le push est désormais neutralisé, avec la convention déjà employée par le clone
Hermes lui-même :

```
remote.origin.pushurl = https://invalid.local/PUSH-DISABLED.git
push.default          = nothing
```

Vérifié : `git push origin <branche> --dry-run` échoue (exit 128), et le clone
Hermes est intact (`918f8c4`, 231 modifications, aucune ref `recovery/`).

Pour rétablir un push le jour où un vrai dépôt distant existe :

```bash
git remote set-url --push origin <url-du-vrai-depot>
```
