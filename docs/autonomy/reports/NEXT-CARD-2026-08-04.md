## Décisions produit en attente, non techniques

Trois surfaces sont **volontairement** différées, avec la raison écrite dans le
code concerné. Les reprendre demande une décision, pas une carte d'implémentation :

1. **Génération de code depuis une spec** (ADR-0017). C'est un produit à part
   entière ; un demi-générateur créerait une seconde autorité sur le code.
2. **Aller-retour de diagrammes** (Mermaid, draw.io, Excalidraw) et **specs
   YAML**. Les deux exigent d'ajouter un parseur tiers — décision supply-chain
   soumise à revue de provenance, pas une tâche de code.
3. **Backend OpenCode réel derrière la conformance suite**. Les adaptateurs
   `opencode`/`unifia` y délèguent aujourd'hui vers un backend bâti sur
   `FakeRuntimeAdapter` : c'est une preuve de contrat, pas du runtime réel.
   Brancher un runtime de session vivant est faisable localement mais dépasse
   une carte bornée.

## Si une seule chose doit être faite ensuite

**Pousser la branche et obtenir un run CI distant.** C'est le seul des cinq
bloquants qui ne demande ni budget ni prestataire — seulement l'autorisation de
pousser, que je n'ai pas prise. Le workflow existe
(`.github/workflows/unifia-conformance.yml`) et le gate passe localement 8/8.

code fait ce qu'il dit, pas qu'un tiers l'a examiné.
