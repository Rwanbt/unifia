# Carte suivante — bootstrap headless réel du Workbench

## Pourquoi celle-ci et pas une autre

Le `WorkbenchServer` expose 17 routes et passe 71 assertions, mais une recherche
`new WorkbenchServer` sur tout le dépôt ne retourne que son propre fichier de
test. **Aucun processus ne l'expose.** Toutes les preuves actuelles sont des
preuves de bibliothèque : elles appellent `server.fetch(new Request(...))` en
mémoire, sans socket, sans serveur HTTP, sans cycle de vie.

Cela bloque simultanément trois résidus de Gate C :

- le consommateur DOM du Generative UI n'a aucun serveur à contacter ;
- l'E2E externe ne peut pas exister sans endpoint ;
- « serveur headless » (Phase 5, critère de sortie Gate A) reste `NON PROUVÉ`.

C'est donc le préalable de tout le reste, et c'est entièrement local.

## Périmètre autorisé

Fichiers pouvant être créés ou modifiés :

- `packages/workbench-server/src/bootstrap.ts` (nouveau)
- `packages/workbench-server/src/index.ts` (export du bootstrap uniquement)
- `packages/workbench-server/test/bootstrap.test.ts` (nouveau)
- `packages/workbench-server/package.json` (script `start`, script `test:bootstrap`)
- `scripts/unifia-conformance.mjs` (ajout de la nouvelle suite)

Interdits : `D:\App\OpenCode\opencode`, les clones Hermes, tout chemin `/ee`,
`packages/enterprise`, `packages/desktop-electron`.

## Travail demandé

1. `createWorkbenchApp(config)` qui assemble `WorkspaceRuntime`,
   `FakeRuntimeAdapter` ou `OpenCodeRuntimeAdapter` selon `config.runtime`,
   `ApprovalCapabilityGate`, un `AuditPort` réel et `HmacTokenAuthenticator`.
2. La clé de signature vient de l'environnement (`UNIFIA_WORKBENCH_SIGNING_KEY`).
   **Refuser le démarrage** si elle est absente ou < 32 octets — jamais de clé
   par défaut, jamais de repli sur `UnauthenticatedPrincipal`.
3. Écoute sur `127.0.0.1` uniquement, port configurable, arrêt propre sur
   `SIGINT`/`SIGTERM` qui ferme les file-sessions ouvertes.
4. Un binaire `bun run start` dans le package.

## Preuve attendue

Un test qui démarre le serveur sur un port éphémère et, **via `fetch` HTTP réel** :

- 401 sans token ; 401 avec signature forgée ;
- 201 sur `register` puis 200 sur `open` avec un token admin signé ;
- 200 sur `files/read` avec `x-unifia-file-session` ;
- **flux SSE consommé avec `EventSource` ou un parseur de trames réel**, pas une
  recherche de sous-chaîne — c'est ce qui aurait attrapé le bug `\\n` corrigé
  dans `eff4a51` ;
- 429 après épuisement du budget ;
- arrêt propre : le port est libéré et une requête ultérieure échoue.

Puis : `node scripts/unifia-conformance.mjs` doit rester à 8/8 avec la nouvelle
suite comptée.

## Conditions STOP

- Si le démarrage exige un secret, un certificat ou un service externe :
  s'arrêter et documenter le blocage, ne pas inventer de valeur par défaut.
- Si `UnauthenticatedPrincipal` apparaît nécessaire hors test : s'arrêter, c'est
  le signe que la conception dérive vers un fail-open.
- Ne pas élargir vers le consommateur DOM dans la même carte.
